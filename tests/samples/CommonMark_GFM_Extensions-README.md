# Markdown 标准程度分类明细

如果严格按 **CommonMark**（Markdown 官方标准）衡量，之前的回复里有不少是**扩展语法**，只是生态里太常见被默认"兼容"了：

## 分类明细

| 语法                                 | 示例                     | 标准程度           | 说明                                                                   |
| :----------------------------------- | :----------------------- | :----------------- | :--------------------------------------------------------------------- |
| 标题 / 列表 / 粗斜体 / 引用 / 代码块 | `#` `**` `` ` ``         | ✅ CommonMark 核心 | 纯标准                                                                 |
| 表格                                 | `\| a \| b \|`           | 🟡 GFM 扩展        | CommonMark 不含表格，GitHub 引入，如今几乎全员支持                     |
| 表格对齐                             | `:---:`                  | 🟡 GFM 扩展        | 同上                                                                   |
| 任务列表                             | `- [x]`                  | 🟡 GFM 扩展        |                                                                        |
| 删除线                               | `~~text~~`               | 🟡 GFM 扩展        |                                                                        |
| 行内 HTML                            | `<u>下划线</u>`          | 🟡 CommonMark 允许 | 标准里属于"内联 HTML"而非 Markdown 语法，渲染器可能禁用（如 Telegram） |
| `<br>` 表格内换行                    |                          | 🟡 HTML 内联       | GFM 表格中常用，但部分渲染器不解析                                     |
| 脚注                                 | `[^1]`                   | 🔴 非标准          | Pandoc/Obsidian 扩展，GitHub 不支持                                    |
| 高亮                                 | `==text==`               | 🔴 非标准          | Obsidian 私有扩展                                                      |
| 上标/下标                            | `^x^` `~x~`              | 🔴 非标准          | Pandoc/Markdown-It 扩展                                                |
| 数学公式                             | `$$...$$`                | 🔴 非标准          | MathJax/KaTeX 约定，需渲染器装插件                                     |
| 自动链接 / 图片                      | `[x](url)` `![alt](src)` | ✅ 标准            |                                                                        |

## 结论

之前的回复是 **CommonMark 超集 + GFM + 私有扩展**的混合物——这在现实世界是常态（Obsidian、Typora、GitHub 各自都往上加东西），但如果你的渲染器是严格 CommonMark 解析器（比如某些 Telegram bot 或轻量 CLI 工具），**脚注、`==高亮==`、上标下标、公式块**这些会直接失效或显示为纯文本。
